Подбор подрядчиков

От условий мероприятия — к трём подходящим вариантам. Сервер проверяет каталог, выбирает кандидатов и возвращает готовые объяснения.

Код фильтрует по городу, категории, занятости, начальной цене, формату, языку и длительности. Затем вычисляет рейтинг с учётом бюджета, семантического соответствия и других факторов. Браузер сохраняет порядок карточек из ответа.

Код решает, языковая модель формулирует

Кандидатов, факты, рейтинг и причины отказа определяет код. Языковая модель получает готовые факты и пишет объяснение; при недоступности модели используется шаблон. Источник указан в каждой карточке. Семантика использует эмбеддинги или лексический резервный вариант.

Быстрый старт#

Запустите uv run uvicorn app:app --port 8012 и откройте http://127.0.0.1:8012/. Форма и примеры используют HTTP API этого сервера.

GET /api/meta возвращает города, категории, форматы, языки, количество профилей каждой категории по городам и границы календаря. Готовые примеры запросов доступны в разделе «Примеры запросов» на странице подбора.

Параметры запроса

POST /api/match принимает JSON. Значения города, категории, формата и языка берите из /api/meta.

ПараметрТипОписание
citystringГород мероприятия.
event_datestringДата YYYY-MM-DD в пределах calendar_start и calendar_end.
event_formatstringФормат события, например «корпоратив».
categorystringКатегория подрядчика.
budget_kztintegerБюджет в тенге, сравнивается с начальной ценой.
duration_hoursinteger | nullНеобязательная длительность; null снимает ограничение.
languagestring | nullНеобязательный язык; null снимает ограничение.

Для даты вне известного календаря сервер возвращает HTTP 422 с полем detail. Интерфейс показывает этот текст и сохраняет условия для исправления.

Результат подбора

Ответ содержит outcome, русский заголовок outcome_title_ru, пояснение shortfall_note, карточки cards, отклонённые профили rejections, размер исходной группы pool_size, число подходящих eligible_count, тип семантики semantic_backend и время timing_ms.

Карточка содержит id, name, category, city, price_from_kzt, флаги synthetic, price_imputed, city_imputed, готовый текст explanation, источник explanation_source (llm или template) и facts. Факты включают дату доступности free_on_date, запас бюджета budget_headroom_pct, лимит max_hours, формат, языки и компоненты рейтинга.

Каждый элемент rejections содержит идентификатор, имя и список reasons с кодом code и русским текстом label. Причины могут пересекаться.

Иллюстрация структуры. Точное описание схемы доступно в документации FastAPI.

Три исхода подбора

matched
Найден хотя бы один подходящий профиль. До трёх карточек в порядке серверного рейтинга.
no_category_in_city
В городе нет выбранной категории. Можно изменить город или услугу.
none_eligible
Категория в городе есть, но никто не прошёл условия. Причины приходят от сервера.

Адаптер api.mjs переводит эти исходы в состояния интерфейса success, absent и filtered. Он не выбирает кандидатов и не сочиняет объяснения.

Цена «от» — ориентир

Попадание в бюджет по начальной цене не гарантирует итоговую стоимость. Синтетические профили и проставленные значения отмечены в выдаче.

Форматирование кода#

Вставьте фрагмент, выберите язык и посмотрите оформление. JSON можно автоматически выровнять. JavaScript подсвечивается с сохранением ваших отступов. Код не выполняется.

JSON будет отформатирован с отступом в два пробела.
