# Промпт для Codex: лайв-тесты в интерфейсе `/tests`

Скопировать целиком в Codex (репозиторий `hack-109052e5-itshich`, ветка от `main`).

---

Ты работаешь в репозитории сервиса подбора подрядчиков (Python 3.12, FastAPI, uv,
pytest; фронт `web/qalau/*.html` + `*.mjs`, без сборки). Сначала прочитай
`README.md`, `app.py`, `matcher/api_types.py`, `matcher/pipeline.py`,
`web/qalau/tests.html`, `web/qalau/api.mjs`, `scripts/test_report.py`,
`docs/research/live-tests.md` (таблица, которую надо воспроизвести в UI) и
`docs/research/stability-tests.md`.

Задача: связать лайв-тесты пайплайна с интерфейсом. На странице `/tests` должен
появиться раздел «Лайв-тесты»: таблица «вход → выход → ключи классификации →
объяснение» для фиксированного набора запросов, с кнопкой прогнать их заново
через живой API и увидеть расхождения. Всё детерминировано и работает офлайн
из сохранённого файла; живой прогон нужен только по кнопке.

## 1. Фикстура запросов и скрипт прогона

- Создай `data/live_tests.json` формата
  `{"generated_at", "git_sha", "model", "cases": [...]}`. Каждый case:
  `{"name", "request": {city, event_date, event_format, category, budget_kzt,
  duration_hours?, language?}, "outcome", "pool_size", "eligible_count",
  "shortfall_note", "timing_ms", "cards": [{id, name, price_from_kzt, flags:[...],
  reasons: [{code, primary, label}], explanation, explanation_source}]}`.
- Набор запросов ровно такой, как в `docs/research/live-tests.md`: 6 из
  `demo/queries.json` плюс 5 дополнительных (декабрь + английский, зал в Астане,
  фотограф с бюджетом впритык, той с казахским, dense с бюджетом −100 000 ₸).
  Список запросов держи в `data/live_tests_requests.json`, чтобы его можно было
  дополнять без правки кода.
- Скрипт `scripts/run_live_tests.py`: читает запросы, гоняет через
  `matcher.pipeline.answer` (с ключом OpenAI объяснения живые, без ключа
  берутся из `data/explanations_cache.json` или шаблон), пишет
  `data/live_tests.json`, печатает таблицу в Markdown в stdout. Флаг
  `--check` сравнивает свежий прогон с сохранённым файлом и завершает с кодом 1,
  если изменился порядок карточек, главные коды причин или тексты объяснений.
  Ключи причин бери из `CardFacts.reasons` результата (см. как это делает
  `matcher/explain.py`), без `AVAILABILITY_SCARCE`.

## 2. API

- В `matcher/api_types.py` добавь в `CardDTO` поле
  `reasons: tuple[ReasonDTO, ...]` (`code`, `primary: bool`, `label` из
  русских подписей; заведи словарь подписей для кодов причин карточек рядом
  с `REASON_LABELS`). Заполняй его в `to_dto` из `CardFacts.reasons`.
  Существующие поля не менять, тесты `tests/test_api.py` дополнить.
- Роут `GET /api/live-tests` в `app.py`: отдаёт `data/live_tests.json`; если
  файла нет, `{"cases": [], "note": "лайв-тесты ещё не прогнаны"}`.

## 3. Страница `/tests`

- В `web/qalau/tests.html` после раздела «Демо-запросы» добавь раздел
  «Лайв-тесты пайплайна». Данные из `/api/live-tests`. Для каждого case
  карточка-строка: слева вход (город, дата, формат, категория, бюджет, часы,
  язык), справа исход и карточки. У каждой карточки: имя, цена «от», бейджи
  флагов, список ключей причин (главная выделена), текст объяснения и
  источник (`llm` / `template`). Для пустых исходов показывай
  `shortfall_note`. Стиль такой же, как у остальной страницы (тёмная тема,
  те же классы), без новых зависимостей.
- Кнопка «Прогнать заново» на каждом case и одна общая «Прогнать все»: POST
  `/api/match` с тем же запросом через `web/qalau/api.mjs`; результат
  показывать рядом с сохранённым и подсвечивать расхождения по трём осям:
  порядок id, главные коды причин, текст объяснения (совпал / изменился).
  Время ответа выводить в мс. Пока идёт запрос, кнопка заблокирована и виден
  статус; ошибка API показывается текстом, страница не ломается.
- Ссылка на раздел из шапки страницы (якорь `#live-tests`).

## 4. Тесты и отчёт

- `tests/test_live_tests.py`: скрипт пишет файл ожидаемой формы на фейковом
  пайплайне; `--check` падает при изменении порядка; `/api/live-tests` отдаёт
  файл и заглушку; `CardDTO.reasons` содержит коды и одну главную.
- e2e в `tests/e2e/test_browser.py`: раздел виден, кнопка «Прогнать заново»
  на фейковом бэкенде показывает «совпало», при подменённом ответе показывает
  расхождение.
- `scripts/test_report.py`: включи в отчёт сводку по лайв-тестам
  (число кейсов, дата прогона, sha).
- README: короткий подраздел «Лайв-тесты» с командами
  `uv run python scripts/run_live_tests.py` и `... --check`, и что показывает
  `/tests#live-tests`.

Правила: объяснение карточки говорит только о самой карточке, никаких имён
других подрядчиков и счётчиков занятых (уже обеспечено бэкендом, в UI ничего
не дописывать). Не трогай `matcher/ranking.py`, `matcher/reasons.py`,
`matcher/explain.py`. Не добавляй зависимости. Модули не длиннее ~250 строк.
Перед завершением: `uv run pytest -q`, `uv run python scripts/run_live_tests.py --check`,
два прогона `scripts/run_demo.py` без ключа совпадают побайтно. Коммит с
понятным сообщением, без `.env`.
