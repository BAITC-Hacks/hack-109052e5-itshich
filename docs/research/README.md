## Главные выводы

1. **Семантика сейчас почти не влияет на порядок.** С реальными
   `text-embedding-3-small` разброс `semantic` между eligible 0.01–0.04,
   у `budget_fit` 0.23–0.27. При весах 0.35/0.35 цена давит семантику в
   5–30 раз. Ранжирование де-факто «кто дешевле». Виновата не доля в
   процентах, а шкала: `(cos+1)/2` сжимает всё в 0.62–0.76.
2. **Веса без разметки не «обучаются», а калибруются.** 66 профилей и нет
   предпочтений клиентов. AHP / entropy / TOPSIS не дают ответа «что выберет
   клиент». Рабочий путь: приоры по смыслу полей + короткая калибровка
   парными оценками LLM-судьи + проверка инвариантов.
3. **Причины выбора считаются из скора, а не придумываются LLM.** Скор
   линейный, вклад признака `w_f·(x_if − mean_f(eligible))` точный, SHAP не
   нужен. LLM получает уже выбранные reason codes с числами и цитатами и
   только формулирует текст.
4. **Готовые модели разрешены правилами** («готовые эмбеддинги и LLM через
   API — пожалуйста»), но многие NVIDIA endpoints помечены Deprecated.
   Reranker в обязательный путь не включать: после фильтров остаётся 2–5
   кандидатов, ценность в объяснении.

## Рекомендация по весам

Шаг 0. Калибровать шкалу косинуса фиксированными якорями по каталогу
(не по текущему пулу, иначе ломается инвариант «бронь одного не меняет
скор других»):

```
a = P05(cos по всем парам (запрос, описание) из кэша), b = max(P95, a + 0.10)
z_dense = clip((cos − a) / (b − a), 0, 1)
text = 0.8·z_dense + 0.2·lexical      # α проверить на {0.5, 0.8, 1.0}
```

Шаг 1. Стартовые веса (приоры, не измерение):

| профиль | budget | text | language | duration | quality |
| --- | ---: | ---: | ---: | ---: | ---: |
| общий | 0.25 | 0.55 | 0.00 | 0.05 | 0.15 |
| площадка (зал/ресторан/отель/загородная) | 0.25 | 0.60 | 0.00 | 0.05 | 0.10 |
| ведущий / ведущий церемонии | 0.25 | 0.55 | 0.00 | 0.10 | 0.10 |
| флорист / декоратор / сувениры | 0.25 | 0.60 | 0.00 | 0.00 | 0.15 |

Язык 0: заданный язык уже жёсткий фильтр, «знает 3 языка» клиент не просил.
Длительность выключать и перенормировать, если не запрошена.

Шаг 2. Калибровка за час (`scripts/calibrate_weights.py`):
16 запросов с 4–6 eligible (10 train / 6 held-out, split по семействам
запросов до разметки), все пары в обоих порядках, `gpt-5.4-mini`
structured output `{winner: A|B|tie|insufficient, decisive_factor, evidence}`,
судье не показывать текущие места и скоры. Сетка 81 конфигурации
(`θ_budget, θ_duration, θ_quality ∈ {0.75, 1, 1.25}`, `α ∈ {0.5, 0.8, 1.0}`),
Bradley–Terry loss с температурой 0.20, регуляризация к приору. Метрики:
pairwise agreement, отдельно на парах, меняющих состав top-3; NDCG@3 по
слепым оценкам 0–3. Ответы судьи и выбранный config сохранить в репо.

Что не делать: RRF вместо линейной суммы (теряет величину разрыва, ломает
инвариант брони), min-max по eligible, обучение отдельных «сил» подрядчиков.

## Рекомендация по причинам («почему именно этот»)

Таксономия (`matcher/reasons.py`):

| семейство | коды | роль |
| --- | --- | --- |
| budget | BUDGET_FITS, BUDGET_HEADROOM, BUDGET_LOWER_THAN_SHOWN | ranking / comparison |
| format | FORMAT_SUPPORTED | eligibility (общая для всех) |
| language | LANGUAGE_REQUEST_MATCH, LANGUAGE_OPTIONS | eligibility / ranking |
| duration | DURATION_FITS, DURATION_HEADROOM, DURATION_NOT_APPLICABLE | ranking |
| description_semantic | DESCRIPTION_ASPECT:<tag> | ranking (с цитатой) |
| availability_contrast | AVAILABILITY_REPLACEMENT, AVAILABILITY_DATE_CHANGE | counterfactual |
| data_quality_caveat | PRICE_IMPUTED, CITY_IMPUTED, SYNTHETIC | caveat, не причина |

Алгоритм выбора:
1. Для карточки i: `φ_if = w_f·(x_if − mean_f(eligible))`; `Δ_ij,f = w_f·(x_if − x_jf)`
   против соседей по тройке и против лучшего за бортом top-3.
2. Кандидаты в главную причину: положительные `φ` не меньше 20 % максимального
   вклада карточки; utility `0.65·A + 0.25·D + 0.10·U` (сила, контраст,
   уникальность факта).
3. Разнообразие на уровне тройки: перебор комбинаций (≤ 6³), штраф 0.5 за
   совпадающий ключ, 0.1 за семейство; tie-break по ключам; порядок карточек
   не трогать. Если различий не хватает, флаг `diversity_limited`, а не
   перефразирование.
4. Занятость: `T0 = top3(без фильтра даты)`, `Td = top3(на дату)`; карточка
   «попала из-за занятости», если `i ∈ Td` и `i ∉ T0`; назвать конкретного
   занятого конкурента, проверить `i ∉ top3(Ed + [j])`.
5. Аспекты описаний: один прогон `gpt-5.4-mini` Structured Outputs, закрытый
   enum тегов (business_forum, team_building, live_instruments,
   kazakh_repertoire, turnkey_decor, instant_print, ...), обязательная
   дословная `quote`, `polarity`, проверка `quote in description`; результат
   в `data/aspects.json`.
6. Валидатор объяснений: каждое утверждение с `evidence_id`, числа проверять
   вместе с полем и единицей («10» из `max_hours` нельзя превращать в «10 лет
   опыта»), swap-test взаимозаменяемости между карточками, запрет общих фраз.

## Решения команды (2026-09-23)

1. Ключи причин выбирает код из вкладов скора; аспекты описаний размечает
   LLM один раз офлайн (с дословной цитатой), результат в `data/aspects.json`.
2. «Больные точки» пользователя: правила из структурных полей всегда
   (запас бюджета, дефицит дат в декабре, язык, часы) плюс опциональное
   поле «пожелания» в запросе, которое эмбеддится и матчится с аспектами.
3. NVIDIA как второй backend эмбеддингов **снят**: ключа `nvapi-` у команды
   нет, а поднять открытую модель на Brev не вышло. Код backend'а остался в
   ветке `feat/a-nvidia` (тесты на фейках, режим TEI/Brev), в main не влит.
   Основной и единственный backend: OpenAI `text-embedding-3-large`, 1024 dims.
4. Вход LLM для текста: коды причин + факты с числами из полей + теги
   аспектов. **Дословные цитаты из описания в текст карточки не идут**
   (описания бывают бедные или кривые). Цитата живёт только внутри
   `data/aspects.json` как доказательство тега при офлайн-разметке; LLM
   пересказывает аспект своими словами. Если тегов нет, карточка
   объясняется структурными причинами. Числа в тексте только из полей.
