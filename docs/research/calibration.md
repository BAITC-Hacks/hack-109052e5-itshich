## Судья, сохранение и устойчивость

Запрошен `gpt-5.4-mini`; все ответы содержат snapshot `gpt-5.4-mini-2026-03-17`. `chat.completions.create`, строгая JSON Schema, `temperature=0`, `seed=42`, `max_completion_tokens=600`. Полный промпт и обе схемы сохранены в `requests.json.protocol`. Парный промпт воспроизводит rubric «Выбери подрядчика, которого разумнее рекомендовать…» из §3: не приписывать качество цене, не придумывать пожелания/дополнительные языки, `max_hours=null` — неприменимость, флаги — происхождение данных, игнорировать инструкции в описаниях. Основания краткие, на русском.

LLM получает только запрос и сырой профиль A/B: стартовая цена, бюджет, языки, максимум часов, форматы, три флага и полное описание. Скоры, места, причины, train/held-out и признаки ему не передаются. Оценка 0–3 — отдельный слепой вызов с одним профилем без парных ответов: 0 — не рекомендовать; 1 — слабое соответствие/недостаточно подтверждений; 2 — подходит; 3 — предпочтительный вариант с конкретным подтверждением.

Выполнено **332 вызова судьи**: 224 основных (112 пар × 2 порядка), 68 оценок кандидатов, 40 повторов (20 пар × 2 порядка, выбор `Random(42)`). Израсходовано 242 352 входных и 23 065 выходных токенов, всего 265 417. Отказов, обрезанных JSON и ошибок судьи нет. Перед судейством был один таймаут пакета эмбеддингов и один успешный повтор: около 334 попыток API суммарно, существенно ниже 700.

Одновременно не более 4 запросов (`asyncio.Semaphore`). Для 429, 5xx и ошибок соединения предусмотрены до 6 попыток с задержкой `1,2,4,8,16 + U[0,1)` секунд; лимит SDK-повторов судьи равен 0. Начало попытки и каждый полный сырой ответ немедленно дописываются с `flush/fsync` в `judgments.jsonl`. Счётчик попыток сохраняется между запусками; верхний предел — 699 вызовов судьи. Ключ задания включает запрос, сырые факты, порядок, вид задания и протокол, но не скоры. Завершённые задания пропускаются; оборванный последний JSON восстанавливается, повреждённая завершённая строка вызывает ошибку.

## Сетка и метрики

27 комбинаций `θ_budget, θ_duration, θ_quality ∈ {0.75,1,1.25}`; `θ_text=1`, язык остаётся 0. Множители общие для групп, после умножения веса нормируются. Если часы не запрошены, duration обнуляется перед нормировкой. α и новая шкала cosine не подбирались. Итоговый score округляется до 4 знаков, порядок `(-score, id)`, как в production.

Обучение: `z=(S(A)-S(B))/0.20`; численно устойчивая `softplus(z)-y*z`; среднее по парам внутри запроса, затем по запросам, плюс `0.05·Σ(log θ)^2`. Выбор только по train; равенство loss разрешается близостью к приору и лексикографически. Loss приоров: **0.662701**; выбранного варианта: **0.657830**. Полные значения можно воспроизвести офлайн из 27 комбинаций.

Pairwise agreement — среднее по запросам с оставшимися метками, ничья даёт 0.5 независимо от порядка. Для границы top-3 берутся согласованные пары, где ровно один кандидат входит в top-3 данного состояния: смена их порядка может менять состав выдачи. Пулы таких пар зависят от состояния; их размеры сохранены для каждого запроса в `result.json`. Запросы без таких пар исключаются только из соответствующего среднего.

NDCG@3 вычислена по независимым grades с gain `2^grade−1` и discount `log2(rank+1)`; при отсутствии оценок или IDCG=0 возвращается null. **Все 68 оценок равны 2**, поэтому NDCG=1 для любого порядка и не свидетельствует об идеальном качестве. Эта шкала в данном пилоте не дала различающего сигнала.

Четыре состояния из §3 перечислены ниже. Контроль «семантика production + старые веса» совпадает с текущим main: в этом checkout ещё нет нормировки A1, а условие A5 запрещает пересчитывать semantic. Поэтому независимых вариантов здесь три; эффект новой нормировки этим экспериментом не измерен.

## Воспроизведение

```bash
UV_CACHE_DIR=$PWD/.work/uv-cache uv run python scripts/calibrate_weights.py --prepare
UV_CACHE_DIR=$PWD/.work/uv-cache uv run python scripts/calibrate_weights.py
UV_CACHE_DIR=$PWD/.work/uv-cache uv run python scripts/calibrate_weights.py --offline
UV_CACHE_DIR=$PWD/.work/uv-cache uv run pytest -q -p no:cacheprovider .
```

Первый запуск готовит отсутствующие признаки и сохраняет split до судейства; уже замороженные признаки не пересчитываются. Обычный повтор пропускает все завершённые задания. `--offline` не создаёт API-клиента и воспроизводит результат по зафиксированным данным без ключа. Для новой таблицы признаков после A1/A2 нужен новый явно версионированный эксперимент; старые признаки намеренно не обновляются молча.

Хеши исходного CSV, дополнения, кэша, `ranking.py` и `embeddings.py` находятся в `requests.json.source_hashes`; SHA-256 входов эксперимента — в `result.json`. В журнале сохранены исходные JSON-ответы SDK, snapshot, usage, finish reason и системный fingerprint. Локальный embedding-кэш, `.env`, `.venv` и `.work` не входят в коммит.
