# Сценарий демо для жюри (5–7 минут)

Запуск перед выступлением:

```bash
uv run uvicorn app:app --port 8000     # открыть http://127.0.0.1:8000
```

Ключ в `.env` не обязателен: демо-запросы воспроизводятся из кэша. С ключом
любой произвольный запрос получает свежее объяснение от модели за 1.5–3 с.

## Как устроен пайплайн (одна фраза на шаг)

```
запрос ──► 1. фильтр ──► 2. ранжирование ──► 3. факты карточек ──► 4. LLM ──► валидатор ──► карточки
              │                 │                     │                            │
              │                 │                     │                            └─ провал → шаблон из тех же фактов
              │                 │                     └─ цена/запас, формат, язык, часы, цитата, отличия от соседей
              │                 └─ 0.35 бюджет + 0.35 смысл описания + 0.10 язык + 0.10 часы + 0.10 качество данных, тай-брейк по id
              └─ город, категория, дата (занятость), цена «от» ≤ бюджет, формат, язык, max_hours; причины отказа сохраняются
```

Ключевой тезис: **кандидатов выбирает и упорядочивает код, модель только
формулирует объяснение по проверенным фактам.** Поэтому порядок детерминирован,
а в объяснении не может появиться факт, которого нет в профиле.

## Ход показа

1. **Плотная категория.** Кнопка «Плотная категория: ведущий, Алматы, осень».
   Ведущих в Алматы 10, на 4 октября условиям соответствуют 5, показаны 3 с
   лучшим баллом. Обратить внимание: у каждой карточки своё основание. Кики
   единственный с английским, Аня Форджер самая низкая цена «от», Сон Гоку
   самая высокая цена, но описание ближе всего к запросу. Раскрыть «Почему
   остальные не попали»: там имена и причины.

2. **Редкая категория.** Кнопка «Редкая категория: флорист». Показано 2 из 3 и
   написано почему: в городе всего 2 флориста. У одного бейдж «цена
   проставлена», у другого «синтетический профиль», и объяснение это
   проговаривает. `max_hours` пустой, поэтому в тексте «работа не привязана к
   присутствию на площадке», а не отказ по часам.

3. **Пара дат.** Кнопки «4 октября» и «5 октября (топ занят)». Тот же запрос,
   другая дата: Кики исчезает, сводка под баннером говорит прямо, кто занят
   5 октября. Это ответ на пункт Definition of Done про занятость.

4. **Пустой результат, вариант А.** Кнопка «Пусто: категории нет в городе».
   Декоратор в Астане. Не ошибка и не пустой экран: сервис говорит, какие
   близкие категории есть в Астане и что декораторы есть в Алматы.

5. **Пустой результат, вариант Б.** Кнопка «Пусто: есть кандидаты, никто не
   проходит». Ведущие в Алматы на 2 октября с бюджетом 500 000 ₸: 10
   кандидатов, все отклонены. Сводка перечисляет причины с именами и ценами:
   заняты, дороже бюджета, не берут формат.

6. **Детерминизм вживую.** Нажать любую кнопку дважды: порядок и тексты
   совпадают. В терминале `uv run python scripts/run_demo.py` делает то же для
   всех шести запросов.

7. **Произвольный запрос** (если есть ключ). Поменять язык на «казахский» или
   дату на декабрьские выходные. В декабре в плотных категориях почти никого
   нет, и сервис так и скажет.

## Ожидаемые вопросы жюри

**Почему не отдать выбор модели?** Тогда пропадают детерминизм и проверяемость.
На 66 профилях жёсткие условия (дата, бюджет, формат) считаются точно, модели
там нечего улучшать. Модель добавляет ценность только в формулировке.

**Откуда «смысл описания»?** Эмбеддинги `text-embedding-3-small`: косинус между
описанием и текстом запроса вида «корпоратив Ведущий Алматы». Векторы лежат в
`data/embeddings.json` по хешу текста, поэтому ранжирование воспроизводимо без
сети. Самое близкое предложение описания попадает в объяснение как цитата.

**Как гарантируете, что модель не выдумывает?** В промпт попадают только факты
карточек и заранее вычисленные отличия. Валидатор отклоняет текст, если в нём
есть число, которого нет в фактах, общая фраза из чёрного списка, больше двух
предложений или два слишком похожих текста. При отклонении весь ответ
заменяется шаблоном из тех же фактов, причина пишется в лог.

**Почему веса именно такие?** Формат, дата и город бинарны и стали фильтрами.
Из непрерывных сигналов только два реально различают прошедших: запас по
бюджету и близость описания, отсюда 0.35 и 0.35. Язык и часы при запросе тоже
фильтры, поэтому 0.10 как тай-брейкеры. Качество данных 0.10, чтобы при прочих
равных первым не стоял профиль с проставленной ценой.

**Цена «от» это же не итоговая цена?** Да, поэтому фильтр отсекает только тех,
у кого стартовая цена уже выше бюджета, а в объяснении всегда «от» и запас в
процентах. Итоговая стоимость зависит от деталей события, это написано под
формой.

**Что с масштабом?** Фильтры идут до эмбеддингов, косинус считается для
десятков кандидатов, а не для всего каталога. Хранилище векторов за
интерфейсом: сейчас файл, в проде колонка pgvector в той же таблице профилей.
Property-based тесты гоняют тысячи синтетических профилей и проверяют
инварианты подбора.

**Что синтетическое?** 13 профилей из исходного датасета помечены
`synthetic`, у 18 проставлена цена, у 8 город. Наши добавленные профили лежат в
`data/synthetic_extra.csv` с `synthetic=True`. Все они видны бейджем на
карточке и упомянуты в объяснении.

**Дата за пределами календаря?** Сервис отвечает текстом, что занятость
известна только на 23.09.2026 — 31.12.2026. Это не один из трёх исходов, а
честный отказ считать то, чего мы не знаем.
