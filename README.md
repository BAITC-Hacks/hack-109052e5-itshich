# Умный подбор подрядчиков (#79-lite)

Сервис принимает параметры заказа (город, дата, тип мероприятия, категория,
бюджет, опционально длительность и язык) и возвращает до 3 карточек
подрядчиков из каталога агрегатора. У каждой карточки есть индивидуальное
объяснение, привязанное к фактам профиля. Кандидатов выбирает и упорядочивает
код, а не модель. LLM пишет только текст объяснения по уже посчитанным фактам.

## Быстрый старт

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync                      # зависимости (без ключа тоже работает)
uv run uvicorn app:app --port 8000
# открыть http://127.0.0.1:8000
```

Ключ OpenAI (нужен только для LLM-объяснений и для пересчёта эмбеддингов):

```bash
cp .env.example .env         # затем вписать OPENAI_API_KEY=sk-...
```

Ключ должен иметь доступ к моделям `text-embedding-3-small` и `gpt-5.4-mini`
(в кабинете OpenAI: Settings → Project → Limits → Model access). Модели меняются
через `LLM_MODEL` и `EMBEDDING_MODEL` в `.env` без правки кода.

Без ключа сервис работает полностью: ранжирование берёт эмбеддинги из
`data/embeddings.json` (лежит в репозитории, 344 вектора), объяснения для
демо-запросов воспроизводятся слово в слово из `data/explanations_cache.json`,
для остальных запросов строятся детерминированным шаблоном из тех же фактов.
В подвале страницы видно источник объяснений (`llm` или `template`) и
семантику (`embeddings` или `lexical`).

Команды:

```bash
uv run pytest -q                       # все тесты (юнит + property-based + API)
uv run pytest -q -m e2e                # проверка страницы в браузере (Playwright)
uv run playwright install chromium     # один раз, для e2e
uv run python scripts/run_demo.py      # 6 демо-запросов, каждый дважды (детерминизм)
uv run python scripts/build_embeddings.py   # пересчитать кэш эмбеддингов (нужен ключ)
uv run python scripts/browser_check.py      # живая проверка страницы: сервер должен быть запущен на :8000
```

Все тесты идут без сети и без ключа. Полный прогон около 15 секунд.

## Что происходит внутри

Пайплайн из четырёх шагов, каждый в своём модуле (`DESIGN.md` описывает
интерфейсы):

1. **Загрузка** (`matcher/data.py`). CSV из 66 профилей превращается в
   неизменяемые объекты. Загрузчик строгий: неизвестный город, формат, язык
   или дата вне окна календаря останавливают запуск с указанием id строки.
2. **Фильтрация** (`matcher/filtering.py`). Пул = подрядчики нужной категории
   в нужном городе. Для каждого считаются все причины отказа: занят на дату,
   цена «от» выше бюджета, не берёт формат, не работает на языке, максимум
   часов меньше запрошенной длительности. Причины сохраняются и показываются
   пользователю в блоке «Почему остальные не попали».
3. **Ранжирование** (`matcher/ranking.py`). Только для прошедших фильтр.
   Итог = 0.35 запас по бюджету + 0.35 близость описания к запросу +
   0.10 языки + 0.10 запас по часам + 0.10 качество данных. При равенстве
   итога порядок по id. Поэтому один и тот же запрос всегда даёт один и тот же
   порядок.
4. **Объяснение** (`matcher/explain.py`). Для каждой карточки собирается набор
   фактов: цена и запас по бюджету, формат, языки, часы, самое релевантное
   предложение описания, флаги качества данных, свободная дата. LLM получает
   только эти факты для показанных карточек и краткую сводку отказов. Ответ
   проходит валидатор: 1–2 предложения, есть конкретные числа из фактов, нет
   общих фраз, карточки не похожи друг на друга, нет чисел, которых нет в
   фактах. Не прошёл валидацию или нет ключа: используется шаблон из тех же
   фактов.

### Три исхода

| Исход | Когда | Что видит пользователь |
| --- | --- | --- |
| Подобрали | есть хотя бы один прошедший фильтр | 1–3 карточки; если меньше трёх, текст объясняет почему |
| В этом городе такой категории нет | пул пуст | сообщение, какие категории есть в городе и есть ли эта категория в другом |
| Кандидаты есть, но ни один не проходит | пул не пуст, все отклонены | сводка по причинам с именами и числами |

Дата вне известного окна календаря (23.09.2026 — 31.12.2026) не является
исходом подбора: сервис отвечает текстом, что занятость на эту дату неизвестна.

### Роль AI

- **Эмбеддинги** (`text-embedding-3-small`) считают близость описания к
  запросу вида «корпоратив Ведущий Алматы». Векторы кэшируются по хешу текста в
  `data/embeddings.json`, поэтому ранжирование воспроизводимо без сети. Порог
  округления до трёх знаков и сортировка по id исключают влияние шума float.
- **LLM** (`gpt-5.4-mini` по умолчанию, `temperature=0`, `seed=42`, таймаут
  8 с) пишет объяснения по фактам. Модель не выбирает и не переставляет
  кандидатов. Ответ проверяет валидатор; провал или ошибка API означают шаблон
  для всего запроса, причина пишется в лог. Удачные ответы кэшируются в
  `data/explanations_cache.json` по хешу запроса, id карточек, модели и версии
  промпта, поэтому повтор запроса даёт тот же текст.

### Ограничения данных

- 66 профилей, из них 13 полностью синтетические, у 18 цена и у 8 город
  проставлены при подготовке датасета. Эти флаги показаны бейджами на карточке
  и упомянуты в объяснении.
- Цена в каталоге это цена «от». Прохождение фильтра означает, что стартовая
  цена укладывается в бюджет, а не что итоговая сумма гарантирована.
- `max_hours = null` означает, что работа не привязана к присутствию на
  площадке (флорист, декоратор, сувениры). Такие профили никогда не отсеиваются
  по длительности.
- Календарь известен только на 100 дней. В декабре 70–80 % дат заняты, это
  свойство сезона, а не ошибка.

## Демонстрация

`demo/queries.json` содержит воспроизводимые запросы на реальных данных.
Кнопки на главной странице подставляют их в форму. Тесты в
`tests/test_service.py` фиксируют ожидаемые id карточек для каждого запроса с
теми же эмбеддингами, что и в проде, поэтому порядок в демо и в тестах один.

| Запрос | Параметры | Исход | Карточки по порядку |
| --- | --- | --- | --- |
| Плотная категория | Ведущий, Алматы, корпоратив, 04.10.2026, 2 000 000 ₸, 4 ч | Подобрали (5 подходят из 10) | HK-35215 Кики, HK-27222 Сон Гоку, HK-29829 Аня Форджер |
| Редкая категория | Флорист, Алматы, свадьба, 04.10.2026, 250 000 ₸ | Подобрали, 2 из 3: в городе всего 2 флориста | HK-39372, HK-90001 |
| Категории нет в городе | Декоратор, Астана | В этом городе такой категории нет; подсказка, где категория есть | — |
| Никто не проходит | Ведущий, Алматы, корпоратив, 02.10.2026, 500 000 ₸ | Кандидаты есть (10), но заняты, дороже бюджета или не берут формат | — |
| Пара дат, A | Ведущий, Алматы, корпоратив, 04.10.2026, 2 000 000 ₸, 4 ч | Подобрали | Кики, Сон Гоку, Аня Форджер |
| Пара дат, B | то же, 05.10.2026 | Подобрали; в сводке видно: Кики и другие заняты 05.10.2026 | HK-88430 Куррапика, HK-77838 Хаул, HK-44733 Буллма |

Время ответа: пустые исходы около 70 мс, с LLM-объяснениями 1.5–3 с, из кэша
объяснений около 120 мс. Полный прогон с повтором каждого запроса делает
`scripts/run_demo.py`.

Примеры объяснений из живого прогона (плотная категория, gpt-5.4-mini):

- Кики: «Единственный из показанных с английским языком; при цене от 900 000 ₸
  остаётся 55 % бюджета, а лимит 10 ч закрывает запрошенные 4 ч.»
- Сон Гоку: «Цена от 1 000 000 ₸ — самая высокая среди показанных, при этом
  остаётся 50 % бюджета; 10 ч лимита хватает на 4 ч, а в описании прямо сказано
  про «опыт более 12 лет».»
- Аня Форджер: «Цена от 700 000 ₸ — самая низкая среди показанных, и при этом
  остаётся 65 % бюджета; 6 ч лимита хватает на 4 ч.»

Что отличает карточки друг от друга, вычисляет код (самая низкая цена,
единственный язык, самый большой лимит часов, описание ближе всего к запросу),
а модель только формулирует. Поэтому объяснения нельзя перепутать между собой,
и в них нет фактов, которых нет в профиле.

## Структура репозитория

```
app.py                 FastAPI: GET /, POST /api/match, GET /api/meta, GET /api/demo
matcher/model.py       общие типы (контракт между модулями)
matcher/data.py        загрузка CSV
matcher/filtering.py   валидация запроса, пул, причины отказа
matcher/ranking.py     формула оценки, порядок, факты карточки
matcher/lexical.py     семантика по ключевым словам (резерв без сети)
matcher/embeddings.py  семантика на эмбеддингах с файловым кэшем
matcher/explain.py     шаблон, LLM, валидатор, факты для промпта
matcher/service.py     сборка исхода и текста «почему меньше»
matcher/pipeline.py    выбор бэкенда, кэш данных, замер времени
web/index.html         страница без сборки и внешних зависимостей
demo/queries.json      демо-запросы с ожидаемыми id
tests/                 юнит, property-based (Hypothesis), API, e2e (Playwright)
DESIGN.md              проектные решения и интерфейсы
docs/worker-reports/   отчёты о реализации по модулям
```

## Масштабирование

Фильтры отрабатывают до эмбеддингов, поэтому косинус считается только для
десятков кандидатов, а не для всего каталога. Кэш векторов спрятан за
интерфейсом `SemanticScorer`: сейчас это файл, на проде та же таблица профилей
с колонкой вектора. Логика подбора при этом не меняется. Property-based тесты
(`tests/test_properties.py`) генерируют тысячи синтетических профилей и
проверяют инварианты: занятые не попадают в выдачу, цена «от» не выше бюджета,
порядок стабилен, `max_hours = null` не отсеивается по часам.
